# drone_harness

`drone_harness` 是基于 ROS 2、MAVROS 与 PX4 的 RGB-D 导航飞行闭环项目。它从原 `drone_agent` 工作副本受控迁移而来；原仓库保持只读。阶段 1 执行链见 [详细实施文档](docs/drone_harness-Phase1-单目标飞行闭环-详细实施文档.md)，阶段 2 任务管理见 [实施文档](docs/drone_harness-Phase2-长指令与子目标管理-实施文档.md)。

> 2026-10-06：阶段 2 已改为 VLM 通过 `update_navigation_plan` 自主管理清单，取代固定拆分和完成 JSON 协议。验证记录见下文。此前悬停恢复、升降、按需观察等改造均属于项目阶段 1。新版真实模型与仿真仍待验证，不宣称导航到达或最终停距验收。只在已抽测的 scene 9、13、21、24 使用仿真深度规则；scene 7 旧起点不用于新测试。真机自主飞行不在本阶段授权内。

## 包与入口

- Python/ROS 包：`drone_harness`
- 仿真入口：`drone_harness_sim`
- 真机入口：`drone_harness_real`（Phase 1 不进行真机自主飞行）
- profile：`drone_harness/config/profiles/sim.yaml` 与 `real.yaml`

示例设置见 `settings.example.json`。本地配置路径为 `~/.config/drone_harness/settings.json`，也可用 `DRONE_HARNESS_SETTINGS` 指向本地文件。API Key 不得提交到仓库。

Phase 1 只使用 `settings.json` 的 `llm` 配置作为唯一图片 VLM。可通过仅在当前进程设置的 `DRONE_HARNESS_LLM_API_KEY`、`DRONE_HARNESS_LLM_BASE_URL` 和 `DRONE_HARNESS_LLM_MODEL` 覆盖示例值；完整 `.../chat/completions` 地址也会归一化为 SDK 所需的基础地址。旧 `vlm`、`detector`、`tracker` 并行模型配置会被拒绝。无飞行接口探针见 `scripts/probe_multimodal_provider.py`，只使用内存中的合成图与假工具结果，不连接 ROS/PX4。


## 阶段 2：长指令与子目标管理

> 2026-10-07 续接与可观察性修订：增加通用完成判断 few-shot、未完成任务引导续接、关键执行事实摘要、有限纠错及可选观察图归档。没有增加高度说明、强制环视、目标测距或第二模型，也没有改变默认降落行为。完整边界与验证见 [阶段 2 最新实施记录](docs/drone_harness-Phase2-长指令与子目标管理-实施文档.md)。

> 2026-10-07：实机已与仿真同步启用阶段 2 清单工具、计划提示、改写/推进及上下文管理。两种正式入口均为九工具；内部显式关闭阶段 2 时仍为八工具。实机六种飞行动作的逐次人工审批、限额、深度检查及原安全交接没有放宽。此为代码同步，不代表实机相机/深度已完成部署或飞行验证。

仍使用原 `drone_harness_sim` / `drone_harness_real` 入口。输入一次导航指令后，同一个 VLM 在正常工具循环中调用 `update_navigation_plan` 创建完整清单，自主标记完成或改写计划，不需要逐段输入“继续”；实机飞行动作仍需逐次审批。两种模式均为原八工具加一个计划工具。不再单独请求模型分类/拆分，也不再从普通回复解析 `subgoal_complete`。

工具参数为 `subgoals`、`finish_action`、`reason`；每项含 `id / description / completion_condition / status / evidence`。每次提交完整清单，允许增删、调序、修改条件与重开目标。硬规则只检查基本字段、非空清单、ID 唯一及最多一个执行中项，不冻结目标、不强制逐段打勾。参数错误保留旧计划并返回反馈供模型修正。阶段 2 对多工具全拒绝、起飞的 `ALREADY_IN_AIR`、下降的 `TARGET_Z_TOO_LOW` 最多提供两次纠正机会（第三次停止）；不自动重放动作。查询和计划更新不重置此计数，成功的有效运动可重置。其他失败及安全退出保持原行为。

“导航先建计划”“依据最新观察判断完成并填写依据”由简短提示引导，不作为清单写入硬门。旧配对观测完成门已移除，但运动后的缓存失效、前进调用时的新深度限制和飞行保护保持不变。全部打勾只进入收尾；降落成功或所要求的空中悬停确认后才记录整体完成，仍不是独立到达核验。

每次请求带最新清单；当前段保留工具历史和最新一张图，仅纯进度推进时压缩完成段，并保留本次计划工具调用/结果对。程序另存最近动作、最近成功动作、最近状态及最近失败的小型事实摘要（来自工具反馈，注明时间，不冒充实时状态），压缩后与任务续接时仍注入。改写清单不压缩当前历史；原日志不删。每轮未建计划沿用 50 次请求预算，建立后总上限为 200 次，包含建计划前请求；改写与自动纠错不重置预算或无位移计数。

未完成任务收到“继续”“降低一点”等引导时保留原指令、完整计划和事实摘要，清除旧图片、深度及审批状态；无位移计数不重置。下一轮不会重放中断动作。完成、实际降落结束或安全交接后的任务不自动续接。明确取消可输入 `取消任务`、`取消当前任务`、`停止任务`、`停止当前任务`、`停止` 或 `停下`；明确替换用 `新任务：…` 或 `换个任务：…`（也接受英文冒号）。这些是有限的明确表达，不做额外模型分类；其他复杂说法由原 VLM 理解，不承诺程序识别。明确取消/替换会隔离旧任务文字，取消本身不请求模型且先复用原安全悬停流程。

终端显示完整清单、完成依据与更新原因；`navigation_plan.jsonl` 记录 `created / updated / resumed / completed / incomplete / cancelled` 快照，原 `tool_calls.jsonl`、`observations.jsonl` 继续保留。多工具整体拒绝逐条记录参数、原因与未执行标记。异常或提前降落不能冒充导航完成。

在使用的 sim/real profile 的 `storage` 下设置 `save_observation_images: true`，重启后启用图片归档（默认 `false`）。图片保存在 `storage.log_dir/session_时间/observations/*.jpg`，`observations.jsonl` 的 `image_path` 为会话内相对路径，可通过观测编号和时间与工具记录关联。保存的是 `observe` 实际提供给 VLM 的 JPEG，不另取图、不保存前进内部取到但未交给模型的图片，不把 base64 写入 JSONL。保存失败给出警告，不改动作结果；不会自动删除旧图片，需留意磁盘容量。

当前方案见 [导航清单工具设计与实施方案](docs/drone_harness-Phase2-导航清单工具-设计与实施方案.md)。历史清单工具改造为专项 57 项、全量 249 项；实机同步后为 253 项。最新验证以阶段 2 实施文档顶部为准。离线测试不能证明 VLM 已能正确判断到达；本轮未启动仿真、未请求真实模型、未测试实机。

## 动作后的稳定等待

在 sim.yaml 或 real.yaml 顶层设置 `post_motion_wait_enabled: true`（默认开启），成功起飞、前进、上升、下降或非零旋转后，runtime 等待再把结果交给模型继续规划。`post_motion_wait_s: 2.0` 是等待秒数，可直接改为 1.0、3.0 等；开关设为 `false` 即关闭。修改后重启 harness 生效。等待仅暂停规划线程，ROS 后台仍正常工作；没有新增模型工具。执行 0 米、旋转 0 度、动作失败、观察、状态查询和降落不会增加这次等待。

```yaml
post_motion_wait_enabled: true  # false 关闭
post_motion_wait_s: 2.0         # 修改等待秒数
```

2026-10-05 补齐开关及可修改秒数后，全量离线测试 **191 项通过**，尚未进行此次延迟的真实仿真验证。

阶段 3 的离线基线为 146 项通过；2026-09-27 提示词与仿真降落调整后为 160 项通过。本次没有进行真实仿真，也未验证 19 米位置指令的实际速度和超调。

系统提示词以“长导航任务飞行规划器”定位模型，但当前仍未新增长任务队列或独立到达核验。模型确认任务完成后应调用 `land`；仿真直接执行降落，不要求人工确认或审批观测绑定，仍复用原位姿、PX4 确认、超时与介入处理。用户要求不降落时按提示词保持空中；实机六个飞行工具仍逐次人工确认。落地成功不等于导航目标已被独立核验，也不把前视相机当作全向避障证明。

`observe(prompt)` 的 schema 提供找路口、辨认店招、转向后重新寻找目标、确认遮挡等示例；不让模型重复索取深度摘要、凭 RGB 估算精确距离或询问飞控状态。系统提示词要求位移或转向后重新观察，并可旋转搜索目标、结合可见环境调整方向或高度绕行；这仍是提示约束，不增加程序强制观察或运动中深度守卫。动作上限集中写入各工具参数描述，随 sim/real 配置生成。

模型收到中文深度摘要，不再收到观测编号与纳秒时间戳；前方、左前、右前统一报告障碍距离，例如“左前障碍距离：5.79 米”。三者采用配置中的同一探测量程（仿真 20 米），距离都是沿当前朝向、相对机体前缘的投影距离，不是斜距，也不是转向后的可飞距离。没检出障碍就报告范围内未检出，缺测就报告未知，不用 20 米或零米代替。侧方仍使用原左右半幅和机体高度带，和中央通道有重叠，并非三等分画面；前进上限仍只由中央通道计算。旧 `side_obstacle_distance_m` 配置保留以兼容本地配置，不再控制侧方距离输出。内部配对、实机审批和日志保持不变。

## 会话与观察描述

`get_state()` 无参数，只返回 `success`、连接、解锁、飞行模式、是否在空中、本地三维位置和参考高度。`position_ned_m` 是本地北/东/下坐标（米）；`height_above_reference_m = 记录的地面 down − 当前 down`，例如地面为 0、当前为 -5 时高度为 5 米。地面参考在确认落地且未解锁时记录，不是实时地形测距；参考缺失时高度为 `null`。未知、无效或断连数据继续如实返回未知。查询不取图、不飞行、不需要人工审批，结果保留在本轮上下文中；不再返回重复空地状态、位置年龄、朝向和固定说明文字。

2026-10-05 精简状态输出后，全量离线测试 **192 项通过**。

系统提示词要求开始导航或状态不确定时先查询，再选择起飞、上升或下降；没有添加每次动作前的强制查询。阶段 1 原工具共八个：observe、get_state、takeoff、forward、up、down、rotate、land；仿真与实机阶段 2 均另加计划工具。左右深度与状态查询补齐后的历史离线测试为 **176 项通过**，当时未启动仿真或请求真实模型。

未建立阶段 2 导航计划时，一次用户输入到本轮结束期间，保留全部 AI 文字、工具调用参数、执行结果和深度摘要。后续 observe 返回新图时，只移除旧观测的图片，保留其文字并标记为历史观测；模型请求最多携带最新一张观察图片。阶段 2 导航按上节规则在切换子目标时压缩完成段。

主模型收到图片后，提示词要求它在下一条回复中先写一两句导航相关的场景描述，需要行动时在同一回复中调用工具。描述会显示在终端、写入日志并留在上下文中；不额外调用视觉模型，也不强制模型补写遗漏的描述。

同一进程内再次输入文字时，继承用户与 AI 的文字对话，包括 AI 场景描述和降落、失败、中断的结束说明；上一轮完整工具协议、原始深度摘要和图片不带入。阶段 2 未完成任务续接时另保留完整清单及有界执行事实摘要，具体规则见上节。飞行审批状态与观测缓存仍按轮重置。退出进程后不恢复历史；没有增加 slash 命令或持久化恢复。

这次记忆调整后的全量离线测试为 **165 项通过**；没有启动仿真或调用真实模型服务。

新任务先由同一个多模态 VLM 接收文字；模型调用 `observe(prompt)` 后，当前 RGB 与同号深度摘要才会交给它。飞行动作后不自动送图，提示词建议模型再次观察。仿真 `forward` 则**每次调用都另取新 RGB-D**，按 20 米决策视距、单次 19 米上限及深度规则计算实际前进距离；深度缺失或无效时不发布前进目标，只返回“未移动”及原因。深度几何计算预留 1 米**计划**净空，请求超限会被缩短并回报请求/指令距离。该余量不是位置 setpoint 的最终物理停距保证；原超时、人工介入和 PX4 安全交接仍有效。连续三次平移无位移会停，成功非零旋转会重置计数。详见[详细实施文档](docs/drone_harness-Phase1-单目标飞行闭环-详细实施文档.md)。
