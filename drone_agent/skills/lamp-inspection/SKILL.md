# Lamp Inspection

## 任务目标

沿路灯排列方向逐个巡检路灯，对每盏路灯完成观察、对准、拍照和损伤分析，最后向用户汇总巡检结果。

## 适用场景

用户要求巡检路灯、检查一排路灯、拍摄每个路灯、分析路灯是否损坏、检查灯杆或灯罩异常时使用。

## 总体原则

- 每次只处理当前画面中最清晰、最适合拍照的一盏路灯。
- 不要同时对多盏路灯下结论，避免漏检或重复统计。
- 每次 `rotate` 或 `move` 后必须重新调用 `analyze_view`。
- 移动到下一盏路灯时，优先使用 `move(x=5, y=0, z=0)` 向前移动 5 米。
- 如果画面不清晰、目标被遮挡或视觉结论不确定，先重新观察，不要直接拍照或继续移动。

## 执行阶段

### 阶段 1：初始化观察

目标：确认画面中是否存在路灯，以及路灯主要排列方向。

可用工具：

```text
analyze_view
```

执行规则：

1. 调用 `analyze_view(target_description="路灯")`。
2. 判断画面中是否存在路灯。
3. 判断路灯是否呈连续排列，例如位于画面左侧、右侧或前方道路两侧。
4. 如果没有发现路灯，按视觉搜索策略小范围观察，不要直接前进。

进入下一阶段条件：

- 当前画面中存在至少一盏可巡检路灯。

失败处理：

- 如果连续观察后仍未发现路灯，向用户说明当前画面未发现可巡检路灯，并等待下一步指令。

### 阶段 2：选择当前路灯

目标：选择当前画面中最清晰、最靠近、最适合拍照的一盏路灯作为本轮巡检对象。

可用工具：

```text
analyze_view
rotate
```

执行规则：

1. 优先选择画面中清晰、无遮挡、距离合适的路灯。
2. 如果路灯偏左或偏右，使用 30 度以内的小角度 `rotate` 微调方向。
3. 如果路灯基本居中，进入拍照阶段。
4. 不要在没有重新观察的情况下连续旋转。

进入下一阶段条件：

- 当前路灯清晰可见，且基本位于画面中心区域。

失败处理：

- 如果当前路灯被遮挡或过远，重新选择画面中更清晰的路灯。

### 阶段 3：拍照与损伤分析

目标：为当前路灯保存照片，并判断是否存在明显损伤。

可用工具：

```text
take_photo
analyze_view
```

执行规则：

1. 先调用 `take_photo` 保存当前路灯照片。
2. 再调用 `analyze_view(target_description="当前路灯是否存在灯杆倾斜、灯罩缺失、灯头破损、灯杆断裂、明显变形或其他可见异常")`。
3. 记录本轮巡检结果：路灯序号、照片路径、是否疑似损坏、异常描述。
4. 如果视觉结论不确定，标记为“需要人工复核”，不要编造损伤结论。

进入下一阶段条件：

- 当前路灯已拍照，并完成损伤分析。

失败处理：

- 如果拍照失败，停止当前巡检并说明原因。
- 如果损伤分析失败，保留照片路径，并说明该路灯需要人工复核。

### 阶段 4：移动到下一盏路灯

目标：沿路灯排列方向前进到下一盏路灯附近。

可用工具：

```text
move
analyze_view
rotate
```

执行规则：

1. 当前路灯完成拍照和分析后，优先调用 `move(x=5, y=0, z=0)` 向前移动 5 米。
2. 移动后必须调用 `analyze_view(target_description="下一盏路灯")`。
3. 如果下一盏路灯偏离画面中心，使用 30 度以内的小角度 `rotate` 微调。
4. 不要为了追踪下一盏路灯进行大幅横向移动。

进入下一轮条件：

- 发现下一盏可巡检路灯后，回到阶段 2。

失败处理：

- 如果移动后没有发现下一盏路灯，可再观察或小角度调整一次。
- 如果仍未发现新的路灯，结束巡检并汇总已完成结果。

## 工具调用约束

推荐单轮巡检顺序：

```text
analyze_view -> rotate -> analyze_view -> take_photo -> analyze_view -> move(x=5, y=0, z=0) -> analyze_view
```

## 安全约束

- 飞行动作仍然必须遵守 HITL、语言介入、超时和安全门。
- 不要在用户介入后继续执行原巡检计划。
- 不要连续执行多个 `move`，每次移动后必须重新观察。
- 不要为了追求拍照角度而接近路灯过近。
- 真机巡检时，如果视觉不确定或用户没有明确授权，优先悬停等待指令。

## 用户介入处理

如果用户在巡检过程中输入新的指令，立即停止当前任务链路。正在执行飞行工具时应进入悬停，等待 LLM 结合用户新指令重新规划。

## 完成条件

- 用户指定数量的路灯全部完成拍照和损伤分析。
- 或连续观察不到新的路灯。
- 或用户要求停止巡检。

完成后必须汇总：

- 已巡检路灯数量。
- 每盏路灯的照片路径。
- 每盏路灯是否疑似损坏。
- 每盏路灯的异常描述或“未发现明显异常”。
- 需要人工复核的项目。

## 停止条件

- 电池、飞行状态、位置状态异常。
- 视觉分析连续失败。
- 拍照失败。
- 用户介入要求停止。
- 当前环境无法继续安全前进。

## 反例

用户只是要求寻找单个目标、普通视觉搜索、查询电池、起飞、降落或返航时，不使用这个 skill。

## 示例

用户：

```text
巡检左侧这一排路灯，对每个路灯拍照并判断是否损坏
```

推荐工具调用顺序：

```text
analyze_view(target_description="路灯")
rotate(direction="left", degrees=20)
analyze_view(target_description="路灯")
take_photo()
analyze_view(target_description="当前路灯是否存在灯杆倾斜、灯罩缺失、灯头破损、灯杆断裂、明显变形或其他可见异常")
move(x=5, y=0, z=0)
analyze_view(target_description="下一盏路灯")
```
