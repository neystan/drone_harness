# S3 RGB-D 配对和几何规则验收

2026-09-25。本阶段只运行合成帧与 ROS 替身的离线测试，没有启动 ROS、PX4、AirSim 或飞行入口。

## 已核实输入与边界

- 现有 AirSim 场景脚本把 `CameraDepth1` 配为 640×480、FOV 94°，同时启用 Scene RGB 和 DepthPerspective；前向相机相对机体中心前移 0.5 m。现有 ROS bridge 对前者发布 `bgr8` 图像、对后者发布 `32FC1` 深度及对应 `camera_info`；图像以 AirSim 响应时间戳发布。AirSim 官方说明 DepthPerspective 是从相机沿各像素射线到物体的距离，不直接等于光轴方向距离。因此本阶段用相机 K 矩阵转换为前向距离，再扣机体前缘。
- 只对明确声明 `perspective_ray_m`、同源相机、同步内参和有限深度执行几何计算。其他单位、编码、错相机、畸变未知、RGB/depth 错配、过期或缺失均给 `forward_max_m=0`。真机 profile 没有借用仿真图像 topic/标定，深度语义设为 `unverified`。
- 仿真 profile 的程序短步总限额由原 20 m 收紧为 0.3 m；制动/超调尚未标定，暂将其余量设为 25 m，大于可用深度的 20 m，故此时即使深度有效也**绝不放行自主前进**。S7 实测标定前只允许桩件验证。

## 实现与测试

- 在原 `Px4Controller` 上增加深度图及 `CameraInfo` 订阅；回调只解码和缓存，不做模型请求或大规模几何计算，原 ROS executor 和 setpoint 定时器不变。
- 有界缓存按采集时间配对 RGB、深度和内参；同时检查采集帧龄与接收后单调时钟龄，动作后要求新帧时间晚于动作结束及时钟误差余量。缺深度可返回带失效原因的 RGB，但不可沿用旧深度。
- 纯计算规则输出同一 `observation_id`、有效性、机体前缘净空、短步上限及左前/右前可见障碍。透视射线先投影到相机光轴，再按相机前移与机体前缘转换；通道内未知像素不视为空地。
- `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q`：44 通过。覆盖配对、旧帧晚到、重复/错时/缺内参、畸变、几何障碍、错误编码/单位/相机和零上限。
