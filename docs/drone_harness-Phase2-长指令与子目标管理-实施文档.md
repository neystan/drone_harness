## 最新修订：主动取证、任务续接与有限纠错（2026-10-07）

用户已审阅实施计划并授权实施、离线验证和推送。本次只扩展阶段 2，不修改原 `drone_agent`、PX4 控制器、飞行动作、深度计算、API 连接或实机审批规则；不启动仿真和真实模型。

### 已实现的五项改动

1. **完成判断提示**：一条通用主动取证原则加三个简短 few-shot，覆盖十字路口中央、经过蓝色卡车、到达白色建筑前停车场。示例明确不是当前环境事实。不规定转向次数，不强制观察完成门，不另发评审请求。没有新增高度说明，不改变默认降落行为。
2. **任务续接**：`runtime/task_memory.py` 将新用户消息和原导航任务分开；未完成计划保留完整条目、原指令与执行摘要，收到引导才续接。清除图像、深度与审批缓存，保留无位移计数，不重放中断动作。已完成、实际降落结束或安全交接后的计划不自动恢复。
3. **关键事实**：保留最近飞行动作、最近成功动作、最近成功状态查询与最近失败四类有界记录，包含记录时间及工具实际返回的结果/位置，不以请求目标代替真实位置；未返回字段未知。每次请求临时注入，纯推进压缩及续接后仍可用。最新失败不会覆盖最近成功动作的事实。没有长期记忆、重启恢复或多图历史。
4. **有限纠错**：阶段 2 下，多工具调用仍全部拒绝；起飞 `ALREADY_IN_AIR` 和下降 `TARGET_Z_TOO_LOW` 经核对均在位置目标下发前返回。上述错误最多提供两次纠正机会，第三次停止；由 VLM 选择下一调用，不自动重试原动作。观察、查询、改计划不抵消计数，有效成功运动重置；请求仍计入本轮原预算。原计划参数错误仍按原方式返回修正反馈。超时、连接/位姿异常、审批拒绝、人工介入及安全退出不自动恢复。
5. **可观察性**：`storage.save_observation_images` 为布尔配置，sim/real 默认关闭。开启后将 `observe` 提供给模型的同一 JPEG 归档到会话 `observations/`，日志记录相对路径与原有观测编号、时间。前进内部未交给模型的 RGB-D 不在此归档范围。保存失败有警告但不影响执行；不保存 base64 或密钥，不删除已有文件。多调用拒绝逐项落盘，白名单拒绝标明 `motion_executed=false`。

### 任务输入边界

- 默认：存在可续接的未完成计划时，新输入视为引导；不另请求分类模型。
- 明确取消：`取消任务`、`取消当前任务`、`停止任务`、`停止当前任务`、`停止`、`停下`。程序复用原悬停交接，记录取消、清除旧任务上下文，不请求模型执行动作。
- 明确替换：`新任务：…`、`换个任务：…`，也接受英文冒号。取消旧任务并隔离其文字后处理新任务。
- 其他复杂自然语言取消/替换表达不是程序解析器支持的语法，仍交给 VLM；不能宣称任意表达均可可靠识别。
- 每次新的用户引导开启一次模型执行轮次，仍使用 50/200 次原预算；轮内自动纠错和清单更新不重置预算。无位移计数在同一导航任务续接时保留，避免用引导绕过停止保护。
- 计划日志增加 `resumed`、`cancelled`；历史中断/失败事件保留，不会被后来的完成覆盖。

## 4. 约定

- 拆分使用同一 client/model，无工具与初始图片；`observe` 仍是模型唯一取图入口。
- 判断与动作规划在同一请求完成；只有当前段可被确认，须有非空依据与当前配对观测。
- 确认同时带工具时明确反馈未执行，不能把拟执行动作当作完成证据。
- 原飞行动作、等待、深度门、无位移判定与异常悬停不改。
- 切换后仅保留最新可用观察与计划摘要，原执行日志不删。
