# drone_harness 阶段 2：长指令与子目标管理实施文档

日期：2026-10-06。依据：[简版设计](drone_harness-Phase2-长指令与子目标管理-简版设计.md)。

## 1. 交付范围

在阶段 1 原执行链上增加固定的“初始拆分 → 当前段检查 → 自动切换 → 收尾”。仅仿真启用；实机保持原审批流程，不新增模型工具。

## 2. 实施顺序

1. 计划与协议：实现轻量计划、拆分解析、每轮判断与摘要；纯离线单元测试通过后提交。
2. 循环接入：仿真启用自动拆分，复用观察与动作；接入顺序推进、收尾、预算、上下文压缩与 JSONL；假模型集成测试通过后提交。
3. 回归交付：全量离线测试、编译、差异检查；更新 README 和验证记录，检查范围后推送 `origin/main`。

## 3. 文件职责

| 位置 | 扩展 |
| --- | --- |
| `runtime/navigation.py` | 计划、解析、摘要、请求构造、完成段压缩 |
| `llm/prompts.py` | 拆分及每轮判断协议 |
| `tools/registry.py` | 上下文保存计划与内部启用开关，八工具不变 |
| `runtime/agent_loop.py` | 固定拆分、完成检查、推进、预算与收尾 |
| `runtime/runtime.py` | 仿真启用、下轮清空、人类可读会话保留 |
| `logging/task_log.py` | `navigation_plan.jsonl` 状态快照 |
| 阶段 2 测试 | 协议、多段执行、原行为回归 |

## 4. 约定

- 拆分使用同一 client/model，无工具与初始图片；`observe` 仍是模型唯一取图入口。
- 判断与动作规划在同一请求完成；只有当前段可被确认，须有非空依据与当前配对观测。
- 确认同时带工具时明确反馈未执行，不能把拟执行动作当作完成证据。
- 原飞行动作、等待、深度门、无位移判定与异常悬停不改。
- 切换后仅保留最新可用观察与计划摘要，原执行日志不删。
- 全部确认再收尾；降落成功或所要求的悬停确认后记录模型判断完成，非独立到达核验。
- 导航总预算 200 次，含拆分；新一轮不恢复旧计划。
