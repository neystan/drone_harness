# drone_harness 阶段 2：长指令与子目标管理简版设计

更新日期：2026-10-06。阶段 1 基线：`f1f9aea`，192 项离线测试通过。

## 1. 目标与边界

输入一次长导航指令，由系统自动拆分、执行、确认和切换子目标，不需要用户逐段输入“继续”。只扩展仿真导航的任务管理，不重构阶段 1 执行链。实机保持原审批流程，不启用此次自主子目标流程。

同一个 VLM 负责拆分、看图、规划动作和判断完成，程序负责保存与顺序推进。不增加子 agent、第二视觉模型、地图、整条路线重规划、长期记忆或重启恢复。

## 2. 固定流程

```text
一次自然语言输入
  → 程序请求同一个 VLM，生成有序子目标
  → 程序激活第一个子目标
  → 每轮 VLM 检查当前段，并选择一个原有工具
  → 未完成：继续观察、查状态或执行原飞行动作
  → 已完成：程序保存依据，自动切换下一段
  → 全部完成：按要求降落或确认悬停，输出结束说明
```

拆分和推进是程序固定环节，**不注册任务管理工具**。八工具及其参数不变。不为每段创建新 runtime，不额外请求评审模型。

## 3. 初始拆分

开始时用一个不带工具的模型请求区分导航和普通交流。普通交流返回原循环；导航生成：

```json
{
  "navigation": true,
  "subgoals": [
    {"description": "沿路到第二个路口", "completion_condition": "经过第一个路口后，新观察支持已到第二个路口"},
    {"description": "左转并穿过桥梁", "completion_condition": "转向与前进反馈、新观察支持已穿过桥梁"},
    {"description": "到达红色建筑前", "completion_condition": "新观察支持已满足红色建筑前的位置关系"}
  ],
  "finish_action": "land"
}
```

普通交流使用 `{"navigation": false}`。拆分为少量有顺序、可观察的导航段，保留地标、方向、计数与条件，不编造坐标或精确距离。每段可以执行多次动作；起飞、绕行和高度调整不必机械拆成独立子目标。降落是收尾，不放进子目标。用户要求不降落时选 `hold`，否则沿用默认 `land`。

## 4. 每轮判断与推进

执行仍使用原八工具，模型文字部分返回：

```json
{"subgoal_complete": false, "evidence": "", "scene_description": "左侧道路入口清晰，目标建筑仍在前方。"}
```

未完成时可在同一回复调用一个工具。确认完成时返回 `true` 和非空依据，不调用工具。工具调用的文字为空时按“未确认完成”处理；普通文字也不算完成，继续循环。明确给出但格式错误的结构拒绝执行，沿用安全停止。

程序只完成当前段，不接受跳段。确认须存在当前 `observe` 的配对 RGB-D 缓存；动作改变视角后原代码清空缓存，必须重新观察才能推进。没有当前观测时保持进度、提示补充观察。若确认同时带工具，补齐“未执行”的工具反馈，不执行该工具，避免把上一段动作带入下一段。

程序检查的是数据与观测是否可用；地标和位置关系是否满足条件仍是 VLM 判断，**不等于独立到达核验**。观测编号只用于内部记录，不发给模型。

## 5. 状态、收尾与停止

轻量 `NavigationPlan` 保存原始指令、有序列表、当前索引、结束动作、各段完成依据与内部观测号。子目标状态为 `pending / in_progress / completed`，任务状态为 `running / finishing / completed / incomplete`。

切换不重置连续无位移计数，也不自动起飞。全部子目标确认后：

- `land`：继续让模型调用原降落工具，成功后才记录任务 `completed`。
- `hold`：复用原安全停止的悬停确认；空中且处于 Offboard 时确认 PX4 悬停。失败走原安全交接，不记录完整完成。

提前降落、工具失败、模型异常、用户介入或预算耗尽记录 `incomplete` 并保存原因，沿用原停止/悬停路径。提前落地不是导航完成。收尾时只允许 `get_state` 与所要求的 `land`，不执行新的导航运动。

活动计划中的普通文字不会结束本轮并等待用户。导航预算为 **200 次模型请求，含拆分**，切换不重置。普通交流沿用原 50 次执行请求，另有一次分类请求。模型超时 600 秒、不自动重试保持不变。

## 6. 最小上下文优化

每次请求临时附加最新摘要：原始指令、已完成段及依据、当前段及条件、后续段、收尾动作、观测是否可用。摘要每次替换，不堆叠，不请求额外模型总结。

当前段保留完整工具协议、反馈与最新一张图。切换后删除已完成段详细执行消息，只保留当前可用的最新观察；完成依据保存在计划摘要，详细执行日志不删除。按完整段删除，不留下孤立 tool 消息。原指令与任务前的文字会话不删除。

下一轮清空计划、图片与观测，继承人类可读的进度摘要及本轮剩余 AI 文字，不继承判断协议或工具结果。退出不恢复。

## 7. 范围与验证

新增 `runtime/navigation.py`，小范围扩展循环、入口、`ToolContext`、提示词和日志。不修改飞行工具、控制器、深度计算、ROS/PX4 启动方式、profile 或模型连接配置。

假 VLM、合成 RGB-D、假控制器验证多段自动推进、动作后观察、完成依据、上下文协议完整、降落/悬停、失败、提前降落、预算与下轮清空。再做阶段 1 全量回归、编译和差异检查。

不启动仿真、不调用真实模型。离线通过不证明真实到达或实机安全。后续应保存 `navigation_plan.jsonl` 与执行日志，独立核对环境和到达。
