# S4 观测注入与 function-calling 循环验收

2026-09-25。本阶段全部通过假客户端、假控制器和合成 RGB-D 帧验证，未启动 ROS、PX4、AirSim 或实际飞行工具。

## 消息合同

- 每条新人工目标重建独立消息列表；首个模型请求前先取得新 RGB，并把 JPEG 图片与**同一观测号**的深度文本放在同一条多模态 `user` 消息。无 RGB 则不请求模型。失效深度仍可带 `forward_max=0` 进入模型，但不能被程序安全门当作前进授权。
- 模型单次回复只允许 0 或 1 个 tool call。多个 call 整体拒绝，并给每个 call ID 补齐拒绝的 `tool` 消息，零动作执行。单动作成功后，动作结束时记录时间，只接受采集时间再晚于该时间与时钟误差余量的新 RGB；下一次模型请求前按 `assistant.tool_calls → tool 结果 → 新多模态 user 观测` 顺序追加。失败、无新 RGB 或成功降落即停止本轮。
- 历史保留当前目标、最近一次动作前后的最多两张图及配对工具结果；日志只保存观测号、时间戳、有效性、上限、原因，不写 JPEG/base64。`TaskState` 记录步号、当前观测、最近动作、连续拒绝/无位移与候选完成文本。候选完成**不触发自动降落或自动验收**。
- 提示词引导 VLM 用 RGB 识别、程序深度规则决定净空，动作后等待新观测，不猜视野外安全。提示词不代替后续 S5 程序安全门。

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q`：52 通过。新增回放覆盖一动作一观测、多个调用零执行、动作失败与后续 RGB 丢失、首帧缺失、图文观测号错配、长轮次图片预算和日志无 base64。测试中没有发飞控命令。
