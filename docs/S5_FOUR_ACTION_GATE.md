# S5 四动作安全门与前进中守卫验收

2026-09-25。本阶段只用合成 RGB-D、假控制器和人工消息替身测试，没有启动飞控、仿真或真机入口。

## 复用范围

- 模型可见动作仍恰好为 `takeoff/forward/rotate/land`；后三者中的转向与降落及起飞继续使用原实现，`forward(distance_m)` 只包装原 `flight.move(context, distance_m, 0, 0)`。底层 `move` 不向 VLM 暴露，侧移、后退和垂直位移无模型参数入口。
- `forward` 程序安全门检查有限正数、profile 短步上限、同号且新鲜的深度规则、当前深度重算、位姿、空中状态和已连接/解锁的 OFFBOARD。超限、布尔值、NaN/Inf、零/负数、失效/过期/变化的观测均返回显式错误，不截短请求距离。仿真标定前制动余量仍使前进上限恒为 0；真机深度语义仍未核实，上限恒为 0，真机 profile 总步长额外收紧为 0.2 m。
- 在原 `move` 的位置目标发布前和每次轮询中调用可选守卫，读取最新深度、位姿和 PX4 状态，检查目标剩余距离。发布后近障、断流、位姿失效、模式异常或人工中断时调用原 `request_confirmed_hover`；PX4 未确认悬停则沿用 `SafetyHandoffRequired` 与 Offboard-loss 交接，不增监视线程、不阻塞 ROS setpoint executor。原 0.3 m 到达容差会把 0.2–0.3 m 短步在起点误判成功，仅受守卫的前进改用 0.05 m 实测到达判据，其他旧动作保持原语义。
- `drone_harness_real` 的四动作无 HITL 豁免；即使历史配置意外列出豁免，程序仍要求逐次批准。提示含动作、参数、观测号、数值上限、失效时间。批准前后核对观测、深度重算限额、飞控状态；过期或变化即拒绝。仿真 `land` 也须单独人工确认，模型“候选完成”不成为降落授权。内部应急悬停仍不等待模型或审批。

## 结果与限制

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q`：78 通过；`python3 -m compileall -q drone_harness` 通过。覆盖数值边界、零侧/垂直位移、过期/近障/位姿/模式变化、发布前拒绝、发布后确认悬停、悬停未确认交接、人工中断、旧到达容差、真机四工具 HITL、降落确认和批准后状态/上限变化。来源只读摘要在提交前复核。

这不是运动安全标定。控制速度、刹停/超调、深度误差、守卫周期及最长盲行距离仍须在 S7 受控仿真中测得；无法证明余量足够时不得放行自主前进。真机飞行仍未获授权。
